# HUD / UI 说明（交接给"改界面样式"的会话）

> 这份文档只讲**界面**。业务逻辑（GSI、状态机、倒计时语义）见 `../README.md` 与
> `实机反馈与待办.md`；改样式**不要动**它们。
>
> 当前产品形态：**一块常驻面板** —— 深灰底 + 左右红竖条 + 居中两行白字
> （状态行 + 「炸弹时限 数值」），观感对齐游戏自己那个"炸弹已被安放"通知框。
> 待机/结束时隐藏，C4 已安放期间常显。拆弹绿字已移除。
> （音频与界面无关：它只影响"数字准不准"，不影响画什么 —— 那代频带能量链路
> 2026-09-16 移除、2026-09-17 以指纹方案回归，见 `实机反馈与待办.md` 第十五 / 二十三节。）

**改版记录（2026-09，从"一行红字"改成"官方风格面板"）**

| 项 | 改前 | 改后 |
|---|---|---|
| 形态 | 左上角标签 + 右上角红色数值（grid 两列） | Canvas 面板：居中两行（状态行 / 标签+数值） |
| 数值字号 | 34pt 等宽 | 16pt（`ui.font_size`） |
| 状态行字号 | 24pt | 12pt（`ui.sub_font_size`） |
| 数值颜色 | 红 `#FF3B30`（语义色直接画） | **画成白色**（深底上白字更清楚），语义色仍由 `render.py` 给出 |
| 底色 | 无（靠色键全透） | `#2E2E36` **不透明**面板 + 左右各 4px 纯红竖条 |
| 位置 | 屏幕右上角（`DEFAULT_MARGIN=24`） | 水平居中、纵向 82%（对齐游戏通知框下方），且**越界会被拉回屏幕内** |
| DPI | 未声明（125%/150% 下会被系统放大成糊的） | 进程声明 `SYSTEM_DPI_AWARE`，留白按 DPI 缩放 |

为什么底色是**不透明深灰**而不是半透明：色键只有"全透/全不透"。实测官方那块面板是
**alpha ≈ 0.63 + 近纯黑基色**（合成后 ≈(49,47,60)），而 `#2E2E36` = (46,46,54) 在明亮画面上
与它几乎一致 —— 详见第七节。**换真 alpha = 换实现**，本轮明确不做。

## 一、UI 相关的文件与职责

| 文件 | 管什么 | 改样式时动不动 |
|---|---|---|
| `c4timer/render.py` | **显示规则**：Snapshot → `View(status, rows)`。纯逻辑、不依赖 tkinter，所以可以被单测 | 本轮**只**把一个内联字面量提成了常量 `ANCHOR_UNKNOWN_TEXT`（行为零变化）；规则/文案/颜色全部冻结 |
| `c4timer/hud.py` | **tkinter 面板**：Canvas 上的底色/红条/两行文字、字号、固定尺寸、透明置顶、DPI、编辑模式拖动、位置持久化与拉回、重绘节流 | 会动（样式全在这里） |
| `c4timer/config.py` 的 `UiConfig` | 字号、字体、缩放、位置、常驻、小数门槛、**面板底色/红条** | 会动（加配置项） |
| `c4timer/app.py` | 接线：ticker 每 20ms 取快照 → `render.build(...)` → `hud.set_view(view)` | 基本不动 |
| `tests/test_render.py` | 「显示层规则」自检 **64 条**断言钉住显示规则 | 本轮**零改动** |
| `tests/test_app.py` 的 [9] / [9b] / **[9c]** | 穿透必须真清掉 `WS_EX_TRANSPARENT` / 只在内容变化时重排 / **面板尺寸不随数字抽动、深底用白字、越界位置拉回** | **必须保持通过**（[9c] 是本次新增的样式护栏） |
| `tools/shot_hud.py` | 把 9 个状态的界面画出来并截图到 `runtime/hud_*.png`，控制台同时列出**语义色与面板色** | 会用来验证 |
| `tools/check_smoothness.py` | 用真实 HUD 量"数字变化间隔的抖动"（读的是 Canvas 上数值行的文字） | 读数卡顿时用它 |
| `tools/mock_panel.py` | **一次性样品脚本**：把面板画在真实游戏截图上，用来定样式（不参与产品逻辑，可删） | 只在"又要改观感"时用 |
| `演示.bat` | 不用游戏：回放 210 个真实报文，看真实行为与观感 | 会用来验证 |

数据流：

```
GSI 线程 ──▶ C4StateMachine ──snapshot()──▶ render.build() ──▶ View ──▶ hud.set_view()
             (state.py)                  (render.py)      (纯数据)     │
                                                                       ▼
                                        hud 自己的 poll(10ms) ──▶ _apply(view) ──▶ Canvas
```

**`View` / `Row` 是唯一的界面契约**（`render.py`）：

```python
Row(label: str, value: str, color: str, big: bool = False)
View(visible: bool, status: str, status_color: str, rows: tuple[Row, ...],
     debug: str = "", gsi_lost: bool = False)
```

`Row.color` / `View.status_color` 是**语义色**（规则），不等于"画在面板上的颜色"（观感）——
两者的映射表在 `hud.py` 顶部，见第三节。`Row.big` 现在没人用了（面板只有两行固定字号），
保留是为了不动 `render.py` 的契约。

## 二、当前视觉规格（真实数值）

**语义色**（`render.py`，规则层）：`RED #FF3B30`、`GREEN #32D74B`（只剩状态行「拆弹成功」在用）、
`GRAY #8E8E93`、`WHITE #FFFFFF`、`YELLOW #FFD60A`、`CYAN #64D2FF`（没用）。

**面板色**（`UiConfig`，观感层）：

| 项 | 值 |
|---|---|
| 面板底色 | `ui.panel_color = #2E2E36`（实测官方合成色 ≈(49,47,60)，这个几乎一致） |
| 左右红竖条 | `ui.panel_bar_color = #FF0000`，`ui.panel_bar_width = 4`（**只有左右两条**，上/下边没有红线——实测官方如此） |
| 色键 | `hud.COLOR_KEY = "#010203"`：面板外凡是这个颜色的像素一律透明。⚠️ 任何颜色都不能等于它 |
| 数值颜色 | 白（`RED`→`WHITE` 映射）；`GRAY`→`#C7C7CC`（提亮，否则 `0.0 / --` 在深底上发糊） |
| 状态行颜色 | 原样（`GRAY` 也提亮）：红/绿/黄都是语义，不能在面板上被改掉 |

**字体**（实际 pt = `round(值 × ui.scale)`，最小 8）：

| 用途 | 字体 | 字号 | 粗细 |
|---|---|---|---|
| 状态行 | `ui.font_family` = Microsoft YaHei UI | `sub_font_size` = 12 | 常规 |
| 数值行（标签+数值） | `ui.font_family`（**原来用等宽 `mono_font`，中文会掉进回退字体所以改了**） | `font_size` = 16 | bold |
| 调试角标 | `ui.mono_font` = Consolas | `11 × scale`（最小 7） | 常规 |

**布局**（`hud.py`，一个 Canvas）：

```
[红条 4px][   状态行（居中）   ][红条 4px]
[         数值行：标签 数值（居中）        ]
```

- `PAD_X = 16`、`PAD_Y = 10`、`GAP = 4`、`BAR_W = 4`（都按 DPI 缩放）；
- **面板宽度是"地板"**：一次性按**最长文案**（`STATUS_TEXT` 全部 + `DEADLINE_PASSED_TEXT`
  + `ANCHOR_UNKNOWN_TEXT` + 最长的数值行）量出来，1080p/scale=1 下 = **239×73**。
  数字每秒变但宽度是地板，所以**读秒期间面板一个像素都不会动**；只有出现更长的文案
  （状态行叠加「 · GSI 断连」、待机那种两行数据）才临时撑开，收回去再回到 239。
- 高度固定 `= 状态行行高 + GAP + 数值行行高 + 2×PAD_Y`；带了 `--debug` 时角标画在面板**下方**（面板外仍然透明）。

**窗口行为**（`hud.py`）：
- `overrideredirect(True)`（无边框）+ `-topmost` + `-transparentcolor COLOR_KEY`；
- 扩展样式 `WS_EX_LAYERED | WS_EX_TOOLWINDOW | WS_EX_NOACTIVATE`
  （+ 穿透时 `WS_EX_TRANSPARENT`）—— **`NOACTIVATE` 必须保留**，否则会抢游戏焦点；
- **进程声明 DPI 感知**（`SetProcessDpiAwareness(SYSTEM_DPI_AWARE)`，必须在建 Tk 之前调），
  留白/红条按 `winfo_fpixels('1i')/96` 缩放；字号是磅值，Tk 自己会跟着 DPI 放大。
  本机是 100% 缩放，**这条没法在本机验证**；
- 默认隐藏（withdraw），`View.visible` 为真时才 `deiconify`；
- 位置是绝对坐标（`ui.pos_x/pos_y`），**越界会被 `_clamp` 拉回屏幕内**（穿透窗口拖不到，
  跑出屏幕就再也找不回来）；没拖过则默认水平居中、纵向 `DEFAULT_Y_RATIO = 0.82`；
- **鼠标穿透与拖动天生冲突**：正常运行时穿透（点不到），只有
  `python -m c4timer run --edit`（或 `启动.bat` 的编辑模式）可拖，松手把位置写进 `config.json`。

## 三、显示规则（已拍板，别推翻）

⚠️ **数值颜色和状态行颜色是两套**：状态行用 `_STATUS_COLOR` =
`{IDLE: GRAY, ARMED: WHITE, DEFUSED: GREEN, EXPLODED: RED}`（GSI 断连时强制变 YELLOW）。
这些都还是**语义色**；面板上画什么见下面那张映射表。

| 情形 | 数值 | 数值语义色 | 状态行（状态行语义色） |
|---|---|---|---|
| 待机 | 两行：`C4 计时器 / 待机`、`(空标签) / 等待安放炸弹` | GRAY | 状态行是空的；默认整窗隐藏，`ui.show_idle=true` 才显示 |
| 已安放，剩余 >15s | 整数，**向上取整**（39.96 → `40`；口径 = 游戏「还剩第几秒」） | RED | 「C4 已安放」(WHITE) |
| 已安放，剩余 ≤15s | 一位小数（9.94 → `9.9`） | RED | 「C4 已安放」(WHITE) |
| 时限已到、还没炸 | `0.0` | GRAY | **「时限已到 · 即将爆炸」**(WHITE) |
| 没看到安放（中途启动） | `时限未知` | YELLOW | 「C4 已安放 · 未看到安放时刻」(WHITE) |
| 炸弹已爆炸 | `0.0` | GRAY | 「炸弹已爆炸」(RED)（1.5s 后隐藏） |
| 拆弹成功 | `--` | GRAY | 「拆弹成功 · 炸弹已解除」(GREEN)（1.5s 后隐藏） |
| GSI 断连 | 数值不变 | 数值不变 | 状态行追加「 · GSI 断连」且变 YELLOW |

数值格式（`render._fmt`）：剩余 `> decimal_below_sec` 时 **`ceil`** 成整数
（"还剩第几秒"，和游戏的 C4 数字对齐），否则保留一位小数（`f"{x:.1f}"`）。
⚠️ 2026-09-16 从 `floor` 改成 `ceil`：实机反馈"倒计时比实际固定快 1 秒，活着/观战都一样"
—— 观战时我们的钟是锁在服务端倒计时上的，所以那 1 秒只能是**数字印低了**。

**面板上的颜色映射**（`hud._VALUE_ON_PANEL` / `_STATUS_ON_PANEL`，只改观感不改规则）：

| 语义色 | 数值行画成 | 状态行画成 |
|---|---|---|
| RED `#FF3B30` | **WHITE**（深底上白字清楚得多） | `#FF3B30`（「炸弹已爆炸」） |
| GRAY `#8E8E93` | `#C7C7CC`（提亮） | `#C7C7CC` |
| 其它 | 原样 | 原样 |

**只有一行数据行**（绿字已删）。标签固定在 `render.ROW_LABEL = "炸弹时限"`。

**已经明确否掉、不要重开的**：不标"估算值/≈"、最后几秒不闪烁/不变色、
标签就叫「炸弹时限」、小数门槛 15 秒、整数取整口径 = **向上取整**（见第三节）、
状态文案保持现状、
**不做半透明底衬**（本轮拍板：用不透明深灰顶替，见第七节）、
**不做棋盘格伪 alpha**（样品实测有肉眼可见的颗粒）。

## 四、三条"别弄坏"的硬约束

1. **重绘节流**：`hud._apply()` 里"`view` 与上次完全相同就一个字节都不碰"，
   以及"尺寸/位置没变就不调 `geometry()`" —— 这是实机反馈"读秒一卡一卡"换来的修复。
   自检 [9b] 断言：25 次相同 View 一次都不重排、数值变了才重排一次。
2. **面板尺寸是地板**：宽度按最长文案预留，`_apply` 里 `max(seed, 实际需要)`。
   数字位数变化（`40`→`9.9`）**绝不许**改面板尺寸 —— [9c] 钉住了这一条。
   注意 Canvas 上的元素只在尺寸变化时重建，平时只 `itemconfigure` 改文字/颜色。
3. **主线程**：tkinter 必须在主线程创建与运行（`app.make_hud()` 在 `run()` 里调）。
   `set_view()` 是线程安全的（加锁只存一份 View），**不要**从 GSI 线程里碰控件。

## 六、配置项（`UiConfig`）与改法

```powershell
python -m c4timer config --list                          # 看全部
python -m c4timer config --set ui.font_size=20           # 数值行字号（原 34 是"一行红字"时代的）
python -m c4timer config --set ui.sub_font_size=14       # 状态行字号
python -m c4timer config --set ui.scale=1.2              # 整体缩放
python -m c4timer config --set ui.panel_color=#2E2E36   # 面板底色（别设成 #010203！）
python -m c4timer config --set ui.panel_bar_width=0      # 去掉红条
python -m c4timer config --set ui.pos_x=1600             # 位置（也可用编辑模式拖）
python -m c4timer config --set ui.show_idle=true         # 待机也显示（确认程序在跑）
python -m c4timer config --set ui.decimal_below_sec=15
```

⚠️ 三个坑：
1. `config --set` 会把**全部字段**写进 `config.json`，等于把当时的默认值**钉住** ——
   以后改代码默认值不会生效。改样式时如果要动默认值，先确认没有 `config.json`（`体检.bat` 会显示来源）。
   本轮改过默认值（`font_size` 34→16、`sub_font_size` 24→12，新增面板三项），
   当前仓库里**没有** `config.json`，所以默认值生效。
2. `config.json` 带 BOM 以前会让整份配置被静默忽略（现在能读 BOM 且会报警）。
3. `ui.panel_color` 不能等于 `hud.COLOR_KEY = #010203`，否则整块面板会被当透明抠掉。

## 七、已知限制 / 已经拍板的技术取舍

1. **半透明底衬做不到，本轮明确不做**（要另立项）。实测官方那块面板是 **alpha ≈ 0.63**、
   基色近纯黑；现在的做法是**不透明深灰 `#2E2E36`**（= 官方在明亮画面上的合成色）。
   代价：**暗背景上会偏亮**（面板比"真正的半透明"更亮），明亮背景上几乎不可区分。
   要真 alpha 得换 `WS_EX_LAYERED` + `UpdateLayeredWindow` 逐像素合成（tkinter 控件画不出来），
   或换渲染后端 —— 那是换实现：`hud.py` 基本重写、[9]/[9b]/[9c] 护栏作废、验证从"看截图"变成实机回归。
2. **棋盘格伪 alpha 已试过并否掉**：Canvas 的 `stipple='gray75'` 平均亮度确实接近官方，
   但点阵纹理肉眼可见（放着不动都看得见），游戏一动更明显。样品留档在 `runtime/mock_*.png`。
3. **色键对抗锯齿边缘不友好（实测）**：15 张截图里共 43852 个"脏边"像素，占字芯的 10~20%，
   机制是 ClearType 逐通道亚像素混合（典型像素 `(102,3,3)`：R 抬到 40%、G/B 停在色键值）。
   这些像素≠色键，所以被当不透明画出来 —— 视觉上就是每个字一圈脏暗描边。
   **换渲染后端才能根治**；现在铺了深底以后它会比"压在游戏画面上"时更显眼。
4. **DPI**：已声明 `SYSTEM_DPI_AWARE` 并把留白按 DPI 缩放，但本机是 100% 缩放，
   **没有实机验证过 125%/150%**（换机器/改缩放要重新看一次）。
5. 调试角标（`view.debug`）仍然只在 `--debug` 时出现，**没有**做成配置开关（避免多一个旋钮）。
6. 多显示器只做了"越界拉回可见区域"，**没有**做"记住哪个屏幕的哪个位置"。
7. 面板宽度按最长文案预留 = 常态下有约 40px 的富余（为了让数字变化时不抽动）。
   想更紧凑只能改成"按内容自适应"，代价是数字位数变化时面板会跳一下宽度。

## 八、本轮已拍板的决定（别再重开）

| 问题 | 决定 |
|---|---|
