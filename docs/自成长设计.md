# 自成长设计（自成长与参考成长）

这份文档把散在 `实机反馈与待办.md` 第 28 / 29 节与教程第 10 节里的设计收拢到一处，
给要改这块代码的人看。**使用者只需要看教程第 10 节。**

目标：使用者零操作，且打得越多越准。分成两条互不干扰的线。

| 线 | 管什么 | 数据来源 | 改动的常数 |
|---|---|---|---|
| 检测侧（参考成长） | 能不能认出播报、认得多准 | 自动落盘的安放片段 + 实战里被采纳的命中 | 参考指纹集合 |
| 时间侧（自成长） | 认出来之后报的时刻准不准 | 每局爆炸时的 `CALIB` 误差 | 音频时间偏置 |

## 一、数据与文件

| 文件 | 内容 | 清空方式 |
|---|---|---|
| `runtime/audio_templates/fp_*.npz` | 参考指纹（最多 5 个） | 删掉即可，下次启动会重建 |
| `runtime/audio_templates/.build_marker` | 上次重建时有多少片段 + 时间戳 | 删掉会让下次启动重建一次 |
| `runtime/calibration_stats.json` | 时间侧的观测与自动修正量 | 删掉即归零，回到手调偏置 |
| `runtime/reference_stats.json` | 检测侧的实战成绩（哪个参考被采纳过几次、分数多少、本代基线） | 删掉即归零 |

**配置里永远只存手动值**（`audio.onset_bias_sec` 等）。自动量单独存在上面两个统计文件里，
运行时相加。这样手调值不会被覆盖，也一眼能看出"程序自己贡献了多少"。

**按参考集分代**：两个统计文件都记着当时的参考集指纹（文件名 + 大小的散列）。参考一换
（重建、增删 npz），旧数据自动作废 —— 因为分数不可跨参考集比较。

## 二、检测侧（参考成长）

**三个触发条件**（都在启动时判断，不打断对局）：

1. 没有参考 + 有片段 => 建参考
2. 已有参考 + 又攒够 5 个新片段 => 重标
3. 已有参考 + 实战分数整体下滑（最近 6 次被采纳命中的中位数 < 本代基线中位数 × 0.6）
   => 重标，且**最多 6 小时一次**（一重建，时间侧的观测就按代作废，不能反复重建）

**择优规则**：候选片段按两段式排序取前 5 —— 先看"实战里被采纳过没有"，同层内再按
"与其它片段的互证总分"。所以参考集会随着对局数越来越贴近实战环境。

**参考的身份**：不用额外字段 —— `build_fingerprints.py` 早就把来源片段名写在 npz 的
`source` 里（形如 `plant_20260917_212925.wav-aligned-len3.2s`）。检测器报命中时带上它，
日志里就是 `参考=plant_20260917_212925.wav`，实战成绩也按这个键累加。

## 三、时间侧（自成长）

每局炸弹爆炸时，用爆炸时刻反推真实时限（真爆比时限晚 1.05 秒），与我们的归零比较，得到
一个**区间**（宽度 = 当时的 GSI 报文间隔）。观测进 `calibration_stats.json`，满足门槛后
自动微调 `audio.onset_bias_sec`。

| 项 | 值 | 理由 |
|---|---|---|
| 最少有效观测 | 8 局 | 少于这个数均值不可信 |
| 单局区间宽度 | <= 1.2 秒 | 稀疏包的局证明不了什么 |
| 均值标准误 | <= 0.08 秒 | 要求不是靠运气凑的 |
| 单次调整 | <= 0.3 秒 | 留余地，下一局再修 |
| 累计修正 | 夹在 ±0.8 秒 | 防止一路跑偏 |

**符号约定**：误差 = 我们的归零 − 真实时限（正 = 偏晚）=> 自动量 = −clamp(平均误差)。

**缺局排除五条**：没有 `CALIB` 的局；区间宽于 0.8 秒；`T0来源` 是旁观位真值（`gsi-truth`）；
音频没生效（`T0来源` 里不含 audio）；回合不在 live（由路径自动满足）。
（第 5 条原文是"不是 CT 方"，2026-09-19 阵营门控取消后改成"不在 live"——
`kept`（播报与锚点一致、保留锚点）也不算音频生效：T0 不是音频定的，记进去会让自成长学错。）

## 四、使用者能看到什么

- 启动日志：`自成长统计：12 局有效观测，平均误差 +0.180s，标准误 0.060s，自动修正量 -0.18s`
- 每次真的调整：一行 `TUNE`；每次采纳命中：日志里是 `参考=<片段名>` 而不是从前的 `模板=fp`
- `体检.bat`（`python -m c4timer doctor`）：自成长摘要 + 统计文件路径

## 五、验证记录（都是演习或实机跑出来的）

| 项 | 结果 |
|---|---|
| 时间侧：8 局偏晚 0.5 秒 | 自动量 `+0.00 -> -0.30`（撞上单次上限） |
| 时间侧：再 30 局偏晚 1.5 秒 | 夹在 `-0.80` 上限 |
| 检测侧：只有 1 个片段 | 跳过互证直接建（新用户第一次标定） |
| 检测侧：32 个片段 | 只保留互证最好的 5 个 |
| 检测侧：攒够新片段 / 新片段不足 | 两种分支都干跑验证 |
| 检测侧：分数整体下滑 | 近期中位 12.5 对基线 41.5 => 判为下滑并触发重标 |
| 参考身份 | 真实片段喂检测器，命中报出 `plant_20260917_124900.wav` |
| 自检污染 | 自检写统计文件曾把真实数据污染成 58 局、自动量顶到 -0.80s，已改为写临时文件 |

## 六、已知边界与以后可做

**2026-09-18 模拟演习抓到并修掉的一处振荡**（值得记住，因为静态推理没发现）：

- 现象：真实节奏模拟里，从第 8 局起**每局都在调**，`-0.30 -> -0.50 -> -0.47 -> …` 一路推
- 根因：滚动窗口里留着"**修正之前**"的旧残差，而观测到的误差其实已经带上了当前生效的自动量
- 修法（两项缺一不可）：估计器用**增量形式**（`new = old − 残差均值`）+ **每次调整后清空观测窗口**
- 验证方式的关键：模拟必须**带反馈**（`观测 = 真实偏晚 + 已生效自动量`）。第一次模拟用的是固定
  误差，因此看起来"收敛了"，其实是假成功 —— 没有反馈的模拟证明不了闭环正确
- 过程中的一次止血：两次修法都没成功时，先把自动施加停用（只累积、只报告），确认不影响计时，
  修好并演习通过后再打开


- 参考最多 5 个（实测参考越多误报上限越高：5 个曾把弱命中误报从 13 顶到 29）
- 下滑判定的"最近 n 次"用全局序号排序（原先按每参考最后时间近似，同一秒内分不出先后）
- `audio.min_hits` **还没有**自动调：它涉及"分数不可跨参考集比较"，等统计系统多跑一段时间再说
- 目前只统计"哪个参考被采纳过"，还没有细到"每次命中对应哪一局、环境如何"
- 已否掉的路：自带音频播放标定（见 `实机反馈与待办.md` 第 26 节）
